# Architecture

## 1. Overview & Toolchain

A Swift package built with **SwiftPM** and the Command Line Tools only (no Xcode).

- **Language:** Swift 6 language mode (strict concurrency). App-target types are `@MainActor`.
- **Target OS:** macOS 14.0+ (developed on macOS 26.x).
- **Frameworks:** Foundation, AppKit, SwiftUI, Charts, CoreGraphics, CoreLocation, ServiceManagement, UserNotifications. No third-party dependencies.
- **Tests:** Swift Testing (`import Testing`), because the Command Line Tools don't ship XCTest. Run them with `./scripts/test.sh`, not bare `swift test` (see [ADR 006](DECISIONS.md)).

| Command | What it does |
|---|---|
| `swift build` | Debug build of everything |
| `./scripts/test.sh` | Unit tests for `SolarDialCore` (wraps `swift test` with the flags Swift Testing needs) |
| `./scripts/build-app.sh` | Release build, wrapped in an ad-hoc signed `build/SolarDial.app` |

If an agent sandbox blocks SwiftPM (`sandbox-exec: sandbox_apply: Operation not permitted`), run the command outside the sandbox. SwiftPM sandboxes its own manifest compilation, and that can't nest.

## 3. Data Flow

```mermaid
flowchart LR
    Tick["30s timer"] --> TC[TintController]
    Notes["App switch / Space change"] --> FS[FullscreenTracker] --> TC
    Loc["LocationProvider: TZ change, wake, CL fix"] --> TC
    Disp["DisplayManager: reconfig / wake"] --> TC
    TC --> Engine["ScheduleEngine (SolarDialCore)"]
    Engine --> TC
    TC -->|"per-display Kelvin"| DM[DisplayManager]
    DM -->|"base table x RGB multipliers"| CG[CGSetDisplayTransferByTable]
```

1. `TintController.refresh` runs every 30 s and whenever an input changes.
2. It resolves coordinates (`LocationResolver`) and asks `ScheduleEngine` for the scheduled Kelvin.
3. `TargetResolver` picks each display's `DisplayTarget` (Kelvin + brightness). Precedence: settings-slider preview, then any disable (temporary, per-app or full-screen → neutral), then movie mode (the chosen Kelvin, full brightness), then the schedule ([ADR 011](DECISIONS.md)).
4. `DisplayManager` fades each display towards its target (30 Hz while fading): Kelvin through mired space, brightness linearly. The table written is `base × RGB multipliers × brightness`.
5. After each refresh: the colour-conflict check, dark-mode sync (edge-triggered on `ScheduleResult.prefersDarkAppearance`, i.e. daylight < 0.5) and the bedtime-reminder check.

### Modes
- **Movie mode:** shows `movieKelvin` (default 4100 K) for `movieMinutes` (default 150). Every disable still wins.
- **Bedtime dimming:** `brightness = 1 − (1 − bedtimeBrightness) × bedtimeWeight`, so it follows the bedtime ramp.
- **Preview:** moving a settings slider shows that Kelvin (or dimming level) on every display for 3 s after the last change.

### Colour-conflict detection
- **Known apps:** `TintController.knownConflictingApps` (bundle IDs; currently f.lux, `org.herf.Flux`) are checked against the running apps.
- **Overwrites:** on each 30 s tick `DisplayManager.checkForOverwrites()` reads each display's table back and compares it with what it last wrote (`GammaTable.approximatelyEquals`, 17 samples, tolerance 0.01). It skips the check while fading, while a reconfiguration reset is pending, and for 5 s after launch or a reset. A mismatch is rewritten and remembered for 10 minutes as an "unknown app" conflict.
- Night Shift and True Tone work below the transfer tables, so they don't show up here.

### Settings window commands
`StatusItemManager` installs `NSApp.mainMenu` independently of its status-item menu. Close, Minimize, Hide and text-editing commands use native selectors and nil targets to follow the responder chain. Settings and Quit target the existing status-item actions. `SettingsWindow.cancelOperation` closes via `performClose` only after controls have had an opportunity to handle Escape, and leaves attached sheets to native cancellation. `AppDelegate.applicationShouldHandleReopen` shows the retained Settings window when the running app is reopened.

### Settings undo
`SettingsStore.settings.didSet` records the old value in `SettingsHistory` (SolarDialCore). Changes less than 1 s apart merge into one step, so a slider drag undoes in one go. At most 50 steps are kept. Reset to Defaults is recorded like any other change.

### Schedule model (`ScheduleEngine`)
Two weights are blended in **mired** space (1e6/K):
- **Daylight**: ramps up over `transitionMinutes`, **ending** at the later of sunrise and wake time, so the screen is already at daytime colour when that instant arrives. Ramps down over `transitionMinutes` starting at sunset (sun at -0.833°). During polar day or night it follows the current solar elevation.
- **Bedtime**: ramps up over `transitionMinutes`, ending at bedtime (= wake time − `sleepMinutes`). Holds, then ramps down over the same morning window and reaches 0 at that anchor. It wraps past midnight correctly.
- Wake is the clock time on that local calendar day (`year`/`month`/`day` components). It is not `Calendar.date(bySettingHour:of:)`, which searches forward and can return tomorrow once the hour has passed.

`kelvin = blend(blend(sunset, day, daylight), bedtime, bedtimeWeight)`. Defaults are 6500 / 3400 / 2300 K, wake time 07:00 and 8 h 30 min of sleep (so bedtime is 22:30), with 60 min transitions.

### Colour (`ColorTemperature`)
The Planckian locus (Krystek approximation) is converted to linear sRGB, divided by the 6500 K values so that 6500 K is exactly white, normalised so the brightest channel is 1, then sRGB-encoded. The multipliers scale the display's **own** transfer table, so calibration is kept.

### Full-screen detection (`FullscreenTracker` + `FullscreenGeometry`)
- It reads `CGWindowListCopyWindowInfo([.optionOnScreenOnly, .excludeDesktopElements])`, which is ordered front to back, and ignores SolarDial's own windows and fully transparent ones.
- For each display, it takes the **topmost** window on layer 0 (normal) or at the shielding level that intersects the display. If that window covers `CGDisplayBounds`, the display is "full screen". It works this way so that a full-screen video on display B is found even while you're working in another app on display A ([ADR 008](DECISIONS.md)).
- `kCGWindowBounds` and `CGDisplayBounds` share a top-left-origin global space. Don't compare against `NSScreen.frame`, which has a bottom-left origin.
- The camera notch: full-screen windows sit below it, so `NSScreen.safeAreaInsets.top` is allowed as slack at the top.
- Bounds and layers don't need Screen Recording permission; window *names* would.
- Checks run on app activation and Space change (again 1 s later, after the Space animation), and on the 30 s tick.
- Known edge case: with an auto-hiding menu bar, a zoomed (green-button-option) window fills the screen and counts as full screen.

### Location (`LocationProvider` + `LocationResolver`)
The order is: manual coordinates, then the last Core Location fix **if it was taken in the current time zone**, then the `zone.tab` coordinates for `TimeZone.current`, then a longitude estimated from the UTC offset. On `NSSystemTimeZoneDidChange` the provider calls `NSTimeZone.resetSystemTimeZone()`, recalculates at once (using `zone.tab` until a new fix arrives) and requests a fresh fix. Wake also requests a fix. Core Location is used only when the bundle declares `NSLocationUsageDescription`, so `swift run` builds use `zone.tab` ([ADR 007](DECISIONS.md)).

## 4. Key macOS APIs & Safety

| Purpose | API | Notes |
|---|---|---|
| Read calibrated table | `CGGetDisplayTransferByTable` | Captured after `CGDisplayRestoreColorSyncSettings()` at launch and after every reconfiguration or wake |
| Apply tint | `CGSetDisplayTransferByTable` | Gamma only. No ICC profiles are written ([ADR 003](DECISIONS.md)) |
| Restore | `CGDisplayRestoreColorSyncSettings()` | On quit and on SIGINT/SIGTERM/SIGHUP (DispatchSource leads to `NSApp.terminate`). On a crash, macOS restores the settings when the process exits |
| Display changes | `CGDisplayRegisterReconfigurationCallback`, `NSWorkspace.didWake/screensDidWake` | Debounced 0.75 s, then tables are recaptured and reapplied |
| Full-screen check | `CGWindowListCopyWindowInfo`, `CGDisplayBounds`, `NSScreen.safeAreaInsets` | See above |
| App / Space events | `NSWorkspace.didActivateApplicationNotification`, `activeSpaceDidChangeNotification` | |
| Location | `CLLocationManager.requestLocation()` (kilometre accuracy) | One-shot fixes only, no continuous tracking |
| Time zone | `NSSystemTimeZoneDidChange` + `NSTimeZone.resetSystemTimeZone()` | No UI, ever |
| Start at login | `SMAppService.mainApp.register()/unregister()` | `.requiresApproval` → button opens Login Items settings |
| Dark Mode | `osascript -e 'tell application "System Events" to tell appearance preferences to set dark mode to …'` | Needs `NSAppleEventsUsageDescription`; one Automation prompt ([ADR 010](DECISIONS.md)) |
| Notifications | `UNUserNotificationCenter` | Skipped when there is no bundle ID; delegate forces banners |

**Conflicts:** macOS Night Shift and the original f.lux both change the display output. Turn them off while testing. f.lux and other table writers are detected (see above); Night Shift isn't.

## 5. Packaging

`scripts/build-app.sh` runs `swift build -c release --product SolarDialApp` and lays out:

```
build/SolarDial.app/Contents/
├── Info.plist      # com.mduppes.solardial, LSUIElement, LSMinimumSystemVersion 14.0, CFBundleIconFile, location + Apple Events usage strings
├── MacOS/SolarDialApp
└── Resources/AppIcon.icns
```

To change the icon, edit `scripts/make-icon.swift`, run `swift scripts/make-icon.swift`, and commit the new `Resources/AppIcon.icns`.

It then signs ad hoc (`codesign --force --sign -`). Because each rebuild changes the ad-hoc signature, macOS may ask for location permission again.


## 6. SolarDial identity and landing page

`com.mduppes.solardial` is the app defaults domain. On launch of the bundled app, `AppDelegate.migrateLegacyPreferences` copies the existing clone's `settings` and `lastLocationFix` from `com.mduppes.sundial`, then `com.mduppes.flux`, only when each value is absent in the new domain. It never reads the vendor's settings. macOS permission and login registration follow the new bundle identity.

`website/dist` is both the landing page's source and static output. It contains local HTML, CSS, JS and the generated app icon, with no external runtime dependencies. An illustrative schedule uses mired blending and clearly labelled sample times. Donate buttons link to the existing Stripe-hosted checkout used by TokenTracking. `scripts/package-download.sh` packages the signed Apple silicon bundle into a ZIP and SHA-256 sidecar under `website/dist/downloads` (ignored in the app repo). Sites publishing uses a separate temporary source checkout, excluding all app code and `reference/` exports. See `website/README.md`.
